# Seq VPS Security

Один bash-скрипт для комплексной защиты VPS. Интерактивное меню, бэкапы
перед каждым изменением, валидация конфигов, лог всех действий.

```text
Debian · Ubuntu · Fedora · RHEL · CentOS · Rocky · AlmaLinux · Oracle Linux
```

Без зависимостей — только стандартные утилиты системы.

## Быстрый старт

Подключись к серверу и выполни **две команды**:

```bash
curl -fsSL https://raw.githubusercontent.com/Fluttershy174PUNK/ezSEQserver/main/seq_vps.sh -o seq_vps.sh
sudo bash seq_vps.sh
```

Готово — откроется сводка сервера и меню. Выход — `Q`.

`chmod +x` не нужен: `sudo bash seq_vps.sh` запускает файл напрямую.

> **Если нет curl** (минимальный образ):
>
> ```bash
> wget -qO seq_vps.sh https://raw.githubusercontent.com/Fluttershy174PUNK/ezSEQserver/main/seq_vps.sh
> sudo bash seq_vps.sh
> ```

> **Скрипт про безопасность — не запускай вслепую.** Хорошая привычка:
>
> ```bash
> less seq_vps.sh      # просмотреть, что скачал (q — выйти)
> ```
>
> Поэтому здесь две отдельные команды, а не `curl … | sudo bash`.

### Загрузка со своего компьютера

Если сервер без интернета или удобнее копировать файл:

```bash
scp seq_vps.sh root@IP_СЕРВЕРА:~/     # со своего компьютера
ssh root@IP_СЕРВЕРА                    # зайти на сервер
sudo bash seq_vps.sh
```

> **Windows:** `scp` и `ssh` есть в PowerShell из коробки.

## Порядок этапов для новичка

Главное правило — **фаервол и SSH-ключ до смены порта**, иначе потеряешь доступ.

```text
 1. Этап 0   Утилиты (micro, mc)
 2. Этап 1   Обновление системы
 3. Этап 2   Создать админ-пользователя с sudo
 4. Этап 4   Установить ему SSH-ключ
 5. ★ ПРОВЕРКА: войди в НОВОМ окне под админом по ключу
 6. Этап 7   Фаервол: открыть SSH-порт (22) и включить
 7. ★ ПРОВЕРКА: текущая сессия не разорвалась
 8. Этап 5   Сменить SSH-порт, отключить вход по паролю
 9. Этап 7   Открыть новый порт в фаерволе (п.1 подхватит его сам)
10. ★ ПРОВЕРКА: войди в НОВОМ окне по новому порту
11. Этап 8   Автообновления безопасности
12. Этап 9   Защита от брутфорса
13. Этап 3   Сменить пароль root (в самом конце)
14. Остальное по желанию: 6, 10–15
```

★ — не иди дальше, пока не убедился, что новый способ входа работает.
**Не закрывай текущую сессию** до успешной проверки в новой.

## Этапы

| # | Этап | Что делает |
|---|------|------------|
| 0 | Утилиты | `micro` (редактор), `mc` (файловый менеджер) |
| 1 | Обновление | `apt update && upgrade && full-upgrade` / `dnf upgrade` |
| 2 | Пользователи | создать, сменить пароль, группы (sudo), удалить |
| 3 | Пароль root | смена пароля root |

| 6 | SFTP-юзер | chroot-пользователь, доступ только к своей папке |
| 7 | Фаервол | UFW (Debian/Ubuntu) или firewalld (RHEL-семейство) |
| 8 | Автообновления | `unattended-upgrades` / `dnf-automatic` + окно перезагрузки |
| 9 | От брутфорса | CrowdSec или Fail2Ban |

| 12 | Время | часовой пояс + NTP-синхронизация |
| 13 | Lynis | аудит безопасности, hardening index |

| 15 | BBR | TCP congestion control (ускорение сети) |
| R | Откат | восстановить файлы этапа из бэкапа |

## Безопасность: как устроено

**Drop-in вместо правки конфига.** Настройки SSH пишутся в
`/etc/ssh/sshd_config.d/00-seq-vps.conf`, основной `sshd_config` не трогается.

> Имя начинается с `00-`, а не `99-`: sshd применяет **первое** найденное
> значение. На облачных образах лежит `50-cloud-init.conf` с
> `PasswordAuthentication yes`, который перебивает любой `99-*` — отключение
> пароля молча не сработает. `00-` гарантирует приоритет.

**Валидация перед рестартом.** Перед каждым `systemctl restart ssh` выполняется
`sshd -t`. Невалидный конфиг → рестарт отменяется, сервер не уходит в lockout.

**SELinux.** На Fedora/RHEL/Rocky/Alma при смене порта автоматически выполняется
`semanage port -a -t ssh_port_t -p tcp <порт>` — без этого sshd не поднимется на
нестандартном порту.

**Фаервол под дистрибутив.** Debian/Ubuntu → `ufw`, RHEL-семейство → `firewalld`.
Они конфликтуют за netfilter, поэтому на RHEL ставится только нативный.

**CrowdSec и firewalld.** У CrowdSec нет firewalld-бонсера, а iptables-бонсер
затирает правила firewalld. На RHEL-семействе ставится движок CrowdSec
(детект) + Fail2Ban с `banaction = firewallcmd-ipset` (баны).

**Fail2Ban** — 3 попытки → бан на 24ч, порт подхватывается из конфига sshd.

## Где что лежит

```text
/opt/seq_vps/
├── seq_vps_YYYYmmdd_HHMMSS.log   лог всех действий
├── .seq_vps_status               статусы этапов (✓ в меню)
└── backups/
    └── YYYYmmdd_HHMMSS/          бэкапы одного запуска
        ├── stage1_update/
        ├── stage5_ssh_config/
        └── ...
```

Откат (`R`) ищет бэкап этапа **во всех сессиях**, берёт последний по времени —
перезапуск скрипта не теряет возможность откатиться.

## Потерял доступ к серверу?

1. Зайди через **консоль провайдера** (VNC / IPMI / KVM в панели хостера).
2. Запусти скрипт → `R` → выбери этап.
3. Или вручную:

```bash
# SSH-порт и настройки
cat /etc/ssh/sshd_config.d/00-seq-vps.conf
sshd -t && systemctl restart ssh

# SELinux (RHEL-семейство)
semanage port -l | grep ssh_port_t

# Фаервол
ufw status numbered          # Debian/Ubuntu
firewall-cmd --list-all      # RHEL/Fedora
```

## FAQ

**Можно запускать повторно?**
Да, скрипт идемпотентен: установленное не переустанавливается, этапы со
статусом ✓ можно пропускать.

**Что делает скрипт с моими конфигами?**
Перед изменением любого файла создаётся бэкап в `backups/<время>/<этап>/`.

**Как посмотреть, что было сделано?**

```bash
cat /opt/seq_vps/seq_vps_*.log
```

**Как обновить скрипт?**
Скачай новую версию и запусти — статусы этапов и бэкапы в `/opt/seq_vps/`
сохранятся.
