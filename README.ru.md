# 4Script

**simple-server-security-script** — один bash-скрипт, который приводит свежий
VPS в защищённое состояние и оставляет его обслуживаемым: интерактивное меню на
сервере или полностью удалённая настройка с ноутбука, бэкап перед каждым
изменением, валидация конфигов перед каждым перезапуском.

```text
Debian · Ubuntu · Fedora · RHEL · CentOS · Rocky · AlmaLinux · Oracle Linux
```

[English version](README.md) · [Manual (how to do it by hand)](docs/manual.md) · [Ручные инструкции](docs/manual.ru.md)

## Быстрый старт

### Удалённо: настроить сервер со своей машины (рекомендуется)

```bash
wget -qO 4script.sh https://raw.githubusercontent.com/Fluttershy174PUNK/4Script/main/4script.sh
bash 4script.sh --remote root@АДРЕС_СЕРВЕРА
```

Пароль спросят **один раз** — чтобы установить ваш SSH-ключ; дальше всё идёт по
ключу. Сама настройка запускается внутри `screen` на сервере, поэтому обрыв связи
или уснувший ноутбук не прервут её на середине.

```bash
bash 4script.sh --remote root@АДРЕС_СЕРВЕРА --attach   # вернуться к идущей настройке
bash 4script.sh --remote admin@10.0.0.5:2222           # не-root и свой порт
bash 4script.sh --remote-help                          # все опции удалённого режима
```

### На самом сервере

```bash
wget -qO 4script.sh https://raw.githubusercontent.com/Fluttershy174PUNK/4Script/main/4script.sh
sudo bash 4script.sh
```

Откроется сводка сервера и меню; выход — `Q`. `chmod +x` не нужен.

> **Скрипт про безопасность — не запускай вслепую.**
>
> ```bash
> less 4script.sh      # просмотреть, что скачал (q — выйти)
> ```
>
> Поэтому здесь две отдельные команды, а не `wget … | sudo bash`.

**Если `wget` не установлен** (минимальные образы):

```bash
sudo apt-get install -y wget || sudo dnf install -y wget || sudo yum install -y wget
```

**Нет интернета на сервере?** Скопируй файл сам:

```bash
scp 4script.sh root@АДРЕС_СЕРВЕРА:~/
ssh root@АДРЕС_СЕРВЕРА
sudo bash 4script.sh
```

## Что делает

Этапы сгруппированы; каждый можно запускать отдельно, статус хранится в
`$DATA_DIR/.seq_vps_status`, поэтому незаконченный прогон можно продолжить.

| # | Этап | Что делает |
| :- | :--- | :--------- |
|  | **Подготовка** |  |
| 0 | Утилиты | `micro` (редактор), `mc` (файловый менеджер) |
| 1 | Обновление | `apt-get update/upgrade/full-upgrade`, `dnf upgrade`, предупреждает о нужной перезагрузке |
|  | **Доступ и вход** |  |
| 2 | Пользователи | создать, сменить пароль, группы (sudo), удалить |
| 3 | Пароль root | смена пароля root |
| 4 | SSH-ключ | вставить / скопировать / просмотреть / удалить, инструкции для Linux, macOS, Windows |
| 5 | SSH-конфиг | порт, парольный вход, root-доступ, MaxAuthTries, пустые пароли, `PerSourcePenalties` |
| 6 | SFTP-юзер | chroot-пользователь в `/srv/sftp/<имя>`, запись в `upload/` |
|  | **Защита** |  |
| 7 | Фаервол | UFW (Debian/Ubuntu) или firewalld (RHEL-семейство); проверка IPv6, предупреждение о Docker, аудит sudo |
| 8 | Автообновления | `unattended-upgrades` / `dnf-automatic` + окно перезагрузки |
| 9 | От брутфорса | CrowdSec или Fail2Ban |
| 10 | DNS | замена резолверов (с учётом systemd-resolved) |
| 18 | Пароли и блокировки | `pam_faillock` (блокирует учётку, а не адрес) и `pam_pwquality` |
| 19 | Аудит событий | `auditd` с базовыми правилами: файлы идентификации, `sudoers`, SSH-конфиг, root-команды, модули ядра |
| 20 | IPv6 | включить или отключить IPv6 (переживает перезагрузку; замечает сессию по IPv6 до того, как её оборвёт) |
|  | **Система и сеть** |  |
| 11 | Fish shell | установка fish |
| 12 | Время | часовой пояс + NTP |
| 13 | Lynis | аудит безопасности, hardening index |
| 14 | Диск | использование, поиск больших файлов |
| 15 | BBR | TCP congestion control |
| 16 | Харденинг ядра | sysctl: KASLR/dmesg/core-дампы, защита hardlink/symlink, ICMP-redirect, rp_filter, SYN-куки |
| 17 | Аудит | порты, учётки (UID 0, без пароля, sudo), SUID/SGID, world-writable, состояние LSM (только чтение) |
| R | Откат | восстановить файлы этапа из бэкапа |
| P | Настройки | показать, что именно применяется сейчас |
| H | Справка | список этапов и рекомендованный порядок |
| Q | Выход | |

### Порядок для нового сервера

Главное правило — **фаервол и SSH-ключ до смены порта**, иначе потеряешь доступ.

```text
 1. Этап 0   Утилиты
 2. Этап 1   Обновление системы
 3. Этап 2   Создать админ-пользователя с sudo
 4. Этап 4   Установить ему SSH-ключ
 5. ПРОВЕРКА: войди в НОВОМ окне под админом по ключу
 6. Этап 7   Фаервол: открыть SSH-порт и включить
 7. ПРОВЕРКА: текущая сессия не разорвалась
 8. Этап 5   Сменить SSH-порт, отключить вход по паролю
 9. Этап 7   Открыть новый порт (п.1 подхватит его сам)
10. ПРОВЕРКА: войди в НОВОМ окне по новому порту
11. Этап 8   Автообновления безопасности
12. Этап 9   Защита от брутфорса
13. Этап 3   Сменить пароль root (в самом конце)
14. Остальное по желанию: 6, 10-20
```

Не иди дальше, пока новый способ входа не работает, и **не закрывай текущую
сессию** до этого.

## Как это устроено внутри

**Drop-in вместо правки основного конфига.** Настройки SSH пишутся в
`/etc/ssh/sshd_config.d/00-seq-vps.conf`, сам `sshd_config` не трогается.

> Имя начинается с `00-`, а не `99-`: sshd применяет **первое** найденное
> значение. На облачных образах лежит `50-cloud-init.conf` с
> `PasswordAuthentication yes`, который перебивает любой `99-*` — отключение
> пароля молча не сработало бы.

**Сокет-активация (Ubuntu 22.10+, Debian 13).** Там слушает не sshd, а
`ssh.socket`, а `Port` из `sshd_config` игнорируется. Скрипт определяет сокет,
пишет override с пустым `ListenStream=` (сбрасывает дефолтный 22) и, поскольку
`sshd-socket-generator` собирает `ListenStream` из **каждой** директивы `Port`,
комментирует чужие `Port`, чтобы старый порт не остался открытым.

**Пароль отключается в двух местах.** Одного `PasswordAuthentication no`
недостаточно: PAM всё равно пускает пароль через keyboard-interactive, поэтому
вместе с ним ставится `KbdInteractiveAuthentication no`.

**Валидация перед каждой записью.** Правка SSH собирается во временном файле и
проверяется через `sshd -t` *до* замены реального файла; отклонённое значение не
попадает в живой конфиг, а пункт меню сообщает об ошибке. `sshd -t` выполняется
и перед каждым перезапуском.

**Старый порт закрывается только после подтверждения нового.** Скрипт сначала
открывает новый порт в фаерволе, проверяет, что порт слушается и принимает
локальное TCP-соединение, затем просит подтвердить вход из нового окна. Если
что-то не подтверждено — старый порт остаётся открытым вместе с точной командой
закрыть его вручную. Это не формальность: более ранняя версия ровно здесь
потеряла доступ к тестовому серверу, а локальная проба не видит NAT и security
group облака.

**SELinux.** На RHEL-семействе смена порта выполняет `semanage port -a -t
ssh_port_t`, а файлы SFTP-chroot получают `restorecon` — иначе sshd не может их
прочитать.

**Fail2Ban.** 3 попытки → бан 24ч. Backend `systemd` требует `python3-systemd`,
`polling` — живого `/var/log/auth.log`. Если нет ни того, ни другого, jail SSH
отключается с явным предупреждением, а не роняет весь сервис.

**DNS.** На системах с `systemd-resolved` файл `/etc/resolv.conf` — симлинк на
stub, поэтому скрипт пишет `/etc/systemd/resolved.conf.d/10-seq-vps.conf`. Под
netplan — предупреждает вместо изменения, которое не переживёт перезагрузку.

**Локаль.** Если текущая локаль не UTF-8 (частый случай при неинтерактивном
SSH), скрипт переключается на `C.UTF-8`. Без этого bash считает длину строк в
байтах: колонки разъезжаются, а многобайтный символ может разрезаться пополам.

## Где что лежит

```text
/opt/4script/          (старые установки продолжают использовать /opt/seq_vps/)
├── 4script_YYYYmmdd_HHMMSS.log   лог всех действий
├── .seq_vps_status               статусы этапов (галочки в меню)
└── backups/
    └── YYYYmmdd_HHMMSS/          бэкапы одного запуска
        ├── stage1_update/
        ├── stage5_ssh_config/
        └── ...
```

Откат (`R`) ищет бэкап этапа **во всех сессиях** и берёт последний по времени —
перезапуск скрипта не теряет возможность откатиться. Каждый файл копируется
через `cp -a` до изменения.

Существующий `/opt/seq_vps/` переиспользуется намеренно: именно там лежат бэкапы
и статус старой установки, и переезд в новый каталог потерял бы их.

## Потерял доступ к серверу?

1. Зайди через **консоль провайдера** (VNC / IPMI / KVM в панели хостера).
2. Запусти скрипт → `R` → выбери этап.
3. Или вручную — см. [docs/manual.ru.md](docs/manual.ru.md).

```bash
cat /etc/ssh/sshd_config.d/00-seq-vps.conf
sshd -t && systemctl restart ssh
systemctl cat ssh.socket             # сокет-активация
semanage port -l | grep ssh_port_t   # SELinux
ufw status numbered                  # Debian/Ubuntu
firewall-cmd --list-all              # RHEL/Fedora
```

## FAQ

**Можно запускать повторно?**
Да. Скрипт идемпотентен, этапы со статусом «выполнено» можно пропускать.

**Что он делает с моими конфигами?**
Перед изменением файл копируется в `backups/<время>/<этап>/`. Клавиша `P`
показывает, что реально применяется сейчас.

**Как посмотреть, что было сделано?**

```bash
cat /opt/4script/4script_*.log      # или /opt/seq_vps/seq_vps_*.log на старых установках
```

**Работает в контейнере?**
В основном да. Часть ключей sysctl в LXC только для чтения, `auditd` не
стартует без `cap_sys_nice`, а BBR требует модуль ядра. Скрипт честно сообщает
об этом, а не делает вид, что всё включилось.

**Можно всё то же сделать руками?**
Да — для этого [docs/manual.ru.md](docs/manual.ru.md) и
[docs/manual.md](docs/manual.md): SSH-ключи, порт, своё имя ключа, фаервол,
обновления, PAM, auditd, по шагам.

## Тесты

```bash
bash -n 4script.sh tests/test_4script.sh
bash tests/test_4script.sh
shellcheck -S warning 4script.sh tests/test_4script.sh
```

Проверяют реестр этапов, дополнение старого статус-файла, разбор директив sshd,
ввод пароля, безопасную обрезку UTF-8, разбор адреса для удалённого режима,
список sysctl и PAM-предикаты, а также прогресс-бар, справку и поведение без
TTY. Без root, без изменений системы, без сети.

Всё перечисленное и рискованные ветки прогнаны на живом стенде (Ubuntu 26.04
LTS, OpenSSH 10.2): смена порта SSH с сокет-активацией, правила фаервола для
нового и старого порта, DNS, PAM включение и выключение с проверкой входа,
харденинг sysctl, IPv6 выключение и включение, удалённый режим с сессией
`screen`.

### TUI: стабильность важнее эффектов

Меню намеренно построчное. Управление стрелками, alternate screen и полноэкранный
рендер зависят от `$TERM`, terminfo и реализации терминала — ненадёжно в SSH,
serial/rescue-консолях и урезанных образах. Скрипт использует обычные
`read`/`printf`: Enter подтверждает, EOF завершает меню, цвета и анимация
отключаются без TTY или при `NO_COLOR`.

Перед продакшеном проверь на VM и не закрывай текущую SSH-сессию.
