# Seq VPS Security

> [English version](README.md)

Один bash-скрипт для комплексной защиты VPS: линейный интерактивный TUI
(без dialog/whiptail/gum), бэкапы перед каждым изменением, валидация конфигов
перед каждым перезапуском и лог всех действий.

```text
Debian · Ubuntu · Fedora · RHEL · CentOS · Rocky · AlmaLinux · Oracle Linux
```

Без зависимостей — только стандартные утилиты системы.

---

## Быстрый старт

```bash
wget -qO seq_vps.sh https://raw.githubusercontent.com/Fluttershy174PUNK/ezSEQserver/main/seq_vps.sh
sudo bash seq_vps.sh
```

Откроется сводка сервера и меню. Выход — `Q`.

`chmod +x` не нужен: `sudo bash seq_vps.sh` запускает файл напрямую.

**Если `wget` не установлен** (минимальные образы):

```bash
sudo apt-get install -y wget || sudo dnf install -y wget || sudo yum install -y wget
```

**Или скопируй со своего компьютера:**

```bash
scp seq_vps.sh root@IP_СЕРВЕРА:~/
ssh root@IP_СЕРВЕРА
sudo bash seq_vps.sh
```

> **Скрипт про безопасность — не запускай вслепую.**
>
> ```bash
> less seq_vps.sh      # просмотреть, что скачал (q — выйти)
> ```
>
> Поэтому здесь две отдельные команды, а не `wget … | sudo bash`.

## Меню

Этапы сгруппированы по смыслу. Пометки статуса в меню берутся из
`/opt/seq_vps/.seq_vps_status`, поэтому недоделанный прогон можно продолжить.

| # | Этап | Что делает |
| :- | :--- | :--------- |
|   | **Подготовка** |   |
| 0 | Утилиты | `micro` (редактор), `mc` (файловый менеджер) |
| 1 | Обновление | `apt-get update/upgrade/full-upgrade`, `dnf upgrade`, предупреждает о нужной перезагрузке |
|   | **Доступ и вход** |   |
| 2 | Пользователи | создать, сменить пароль, группы (sudo), удалить |
| 3 | Пароль root | смена пароля root |
| 4 | SSH-ключ | вставить / скопировать / просмотреть / удалить, инструкции для Linux, macOS, Windows |
| 5 | SSH-конфиг | порт, парольный вход, root-доступ, MaxAuthTries, пустые пароли |
| 6 | SFTP-юзер | chroot-пользователь в `/srv/sftp/<имя>`, запись в `upload/` |
|   | **Защита** |   |
| 7 | Фаервол | UFW (Debian/Ubuntu) или firewalld (RHEL-семейство) |
| 8 | Автообновления | `unattended-upgrades` / `dnf-automatic` + окно перезагрузки |
| 9 | От брутфорса | CrowdSec или Fail2Ban |
| 10 | DNS | замена резолверов (с учётом systemd-resolved); список заменяется целиком, режима «добавить» нет |
|   | **Система и сеть** |   |
| 11 | Fish shell | установка fish |
| 12 | Время | часовой пояс + NTP |
| 13 | Lynis | аудит безопасности, hardening index |
| 14 | Диск | использование, поиск больших файлов |
| 15 | BBR | TCP congestion control |
| R | Откат | восстановить файлы этапа из бэкапа |
| H | Справка | список этапов и рекомендованный порядок |
| Q | Выход | |

## Порядок для нового сервера

Главное правило — **фаервол и SSH-ключ до смены порта**, иначе потеряешь доступ.

```text
 1. Этап 0   Утилиты (micro, mc)
 2. Этап 1   Обновление системы
 3. Этап 2   Создать админ-пользователя с sudo
 4. Этап 4   Установить ему SSH-ключ
 5. ★ ПРОВЕРКА: войди в НОВОМ окне под админом по ключу
 6. Этап 7   Фаервол: открыть SSH-порт (22) и включить
 7. ★ ПРОВЕРКА: текущая сессия не разорвалась
 8. Этап 5   Сменить SSH-порт, отключить вход по паролю
 9. Этап 7   Открыть новый порт в фаерволе (п.1 подхватит его сам)
10. ★ ПРОВЕРКА: войди в НОВОМ окне по новому порту
11. Этап 8   Автообновления безопасности
12. Этап 9   Защита от брутфорса
13. Этап 3   Сменить пароль root (в самом конце)
14. Остальное по желанию: 6, 10–15
```

★ — не иди дальше, пока не убедился, что новый способ входа работает.
**Не закрывай текущую сессию** до успешной проверки в новой.

## Безопасность: как устроено

**Drop-in вместо правки конфига.** Настройки SSH пишутся в
`/etc/ssh/sshd_config.d/00-seq-vps.conf`, основной `sshd_config` не трогается.

> Имя начинается с `00-`, а не `99-`: sshd применяет **первое** найденное
> значение. На облачных образах лежит `50-cloud-init.conf` с
> `PasswordAuthentication yes`, который перебивает любой `99-*` — отключение
> пароля молча не сработает. `00-` гарантирует приоритет.

**Сокет-активация (Ubuntu 22.10+, Debian 13).** Там слушает не sshd, а
`ssh.socket`, а `Port` из `sshd_config` игнорируется. Смена порта без правки
сокета отчитывается успехом, старый порт остаётся открыт, новый не
открывается — мгновенный lockout. Скрипт определяет сокет и пишет
`/etc/systemd/system/ssh.socket.d/10-seq-vps.conf` с пустым `ListenStream=`
(сбрасывает дефолтный 22) и `ListenStream=<порт>`, затем перезапускает
`ssh.socket`.

**Пароль отключается в двух местах.** Одного `PasswordAuthentication no`
недостаточно: PAM всё равно пускает пароль через keyboard-interactive.
Вместе с ним ставится `KbdInteractiveAuthentication no` (и снимается тоже
вместе).

**Валидация перед рестартом.** `sshd -t` выполняется перед каждым
`systemctl restart ssh`, включая два рестарта в этапе SFTP. Невалидный
конфиг отменяет рестарт — опечатка не оставит сервер без SSH.

**SELinux.** На Fedora/RHEL/Rocky/Alma при смене порта выполняется
`semanage port -a -t ssh_port_t -p tcp <порт>` — без этого sshd не поднимется
на нестандартном порту. Файлы SFTP-chroot получают `restorecon`, иначе sshd
не может их прочитать (метка `user_home_t` вместо типа chroot).

**Пароль SFTP не блокируется глобальным конфигом.** Блок
`Match User <имя>` заново включает `PasswordAuthentication` для одного
пользователя, а `Match` переопределяет глобальную секцию — проверено через
`sshd -T -C user=<имя>` на сгенерированных файлах. Глобальный drop-in при
этом продолжает действовать для всех остальных, включая `root`. Учти, что в
`Match` можно задать лишь часть директив; `PasswordAuthentication`,
`KbdInteractiveAuthentication`, `ChrootDirectory`, `ForceCommand` и
`AuthorizedKeysFile` в эту часть входят.

**Фаервол под дистрибутив.** Debian/Ubuntu → `ufw`, RHEL-семейство →
`firewalld`. Они конфликтуют за netfilter, поэтому настраивается только
нативный.

**CrowdSec и firewalld.** У CrowdSec нет firewalld-бонсера, а iptables-бонсер
затирает правила firewalld. На RHEL-семействе ставится движок CrowdSec
(детект) + Fail2Ban с `banaction = firewallcmd-ipset` (баны). Коллекция
`crowdsecurity/sshd` устанавливается и проверяется — без неё движок работает,
но SSH-атаки не видит.

**Fail2Ban.** 3 попытки → бан на 24ч, порт подхватывается из конфига sshd.
Backend `systemd` требует `python3-systemd` (на Debian он не в зависимостях),
а `polling` — живого `/var/log/auth.log` (нет без rsyslog). Если нет ни того,
ни другого, jail SSH отключается с явным предупреждением, а не роняет весь
сервис молча.

**DNS.** На системах с `systemd-resolved` файл `/etc/resolv.conf` — симлинк
на stub, который перегенерируется, поэтому скрипт пишет
`/etc/systemd/resolved.conf.d/10-seq-vps.conf`, а не перезаписывает файл.
Под netplan — предупреждает, вместо изменения, которое не переживёт boot.

## Где что лежит

```text
/opt/seq_vps/
├── seq_vps_YYYYmmdd_HHMMSS.log   лог всех действий
├── .seq_vps_status               статусы этапов (✓ в меню)
└── backups/
    └── YYYYmmdd_HHMMSS/          бэкапы одного запуска
        ├── stage1_update/
        ├── stage5_ssh_config/
        └── ...
```

Откат (`R`) ищет бэкап этапа **во всех сессиях** и берёт последний по
времени — перезапуск скрипта не теряет возможность откатиться.

Каждый файл копируется через `cp -a` до изменения; если этап падает, его
файлы восстанавливаются из того же каталога.

## Потерял доступ к серверу?

1. Зайди через **консоль провайдера** (VNC / IPMI / KVM в панели хостера).
2. Запусти скрипт → `R` → выбери этап.
3. Или вручную:

```bash
# SSH-порт и настройки
cat /etc/ssh/sshd_config.d/00-seq-vps.conf
sshd -t && systemctl restart ssh

# Сокет-активация (Ubuntu 22.10+, Debian 13)
systemctl cat ssh.socket
systemctl restart ssh.socket

# SELinux (RHEL-семейство)
semanage port -l | grep ssh_port_t

# Фаервол
ufw status numbered          # Debian/Ubuntu
firewall-cmd --list-all      # RHEL/Fedora
```

## FAQ

**Можно запускать повторно?**
Да, скрипт идемпотентен: установленное не переустанавливается, этапы со
статусом ✓ можно пропускать.

**Что делает скрипт с моими конфигами?**
Перед изменением любого файла создаётся бэкап в `backups/<время>/<этап>/`.

**Как посмотреть, что было сделано?**

```bash
cat /opt/seq_vps/seq_vps_*.log
```

**Как обновить скрипт?**
Скачай новую версию и запусти — статусы этапов и бэкапы в `/opt/seq_vps/`
сохранятся.

**Работает в контейнере?**
В основном да. BBR требует модуль ядра, которого в контейнере может не быть;
скрипт сообщает об этом, а не делает вид, что всё включилось. Настройки сети
(DNS, фаервол, BBR) правильнее делать на хосте.

## Тесты

Статические и юнит-проверки — без root, без изменений системы, без сети:

```bash
bash -n seq_vps.sh tests/test_seq_vps.sh
bash tests/test_seq_vps.sh
shellcheck -S warning seq_vps.sh tests/test_seq_vps.sh
```

Проверяют реестр этапов (уникальность номеров и ключей, существование
функций, полнота списка), генерацию статус-файла, разбор директив sshd, ввод
пароля, прогресс-бар и поведение без TTY.

### TUI: стабильность важнее эффектов

Меню намеренно остаётся построчным. Управление стрелками, alternate screen и
полноэкранный рендер зависят от `$TERM`, terminfo и реализации терминала. Это
ненадёжно в SSH, serial/rescue-консолях и урезанных образах. Скрипт использует
обычные `read`/`printf`: Enter подтверждает ввод, EOF завершает меню, цвета и
анимация отключаются без TTY или при `NO_COLOR`. Внешние `dialog`, `whiptail`
и `gum` не нужны.

Перед продакшеном проверь сначала на VM и не закрывай текущую SSH-сессию.
